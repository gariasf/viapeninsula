# The bundle is built by region: a track file and a Trips file for each

ADR-0010 kept the bundle one file through all of Cercanías and said that before long distance it's split by region (`docs/research/bundle-at-scale.md`: all of Spain's Cercanías is 1.3 MB brotli of track in one file, but with long distance 8.1 MB, which crashed the page, and one Network's failure fails the whole build). #256 is the split's first slice, decided with the maintainer at its triage on 4 Oct 2026: the bundle is built by region, and the page still loads every region. Loading only the regions in view is #266, and splitting the snapshot, counted first, #267.

- **A region is Networks loaded together,** not an administrative region: a Network on its own, or a group whose Lines share Stretches (ADR-0006), which one line graph draws side by side. Each Network's config has a `region`, its own ID where it names none. Catalonia's four, whose Lines share Stretches in 35 places, are `catalonia`; with the other 14 núcleos that makes 15. Madrid's C2 runs on to Guadalajara, in another autonomous community, and is in Madrid's region.
- **Long distance will be a region of its own,** loaded at every view, with its own graph. Its Networks aren't in `NETWORKS` yet (#259), but their configs name it already, `long-distance` (`EVERYWHERE`), which the manifest gives no extent, so that the page loads it at every view once they are (#266). How its Lines share Stretches with a region's is #262's call, from #259's traces. Its shapes come in the track file as the pieces of track they share, as every region's do (ADR-0015, #257).
- **Each region is built on its own, one after another:** its Networks read, traced and placed as before, then its own line graph (ADR-0007), then its files: one track file, the same for each day built together, and a Trips file for each day, named for the region and their content, as `days/track-catalonia-<hash>.json` and `days/2026-10-10-catalonia-<hash>.json`. A Stretch's centreline and the curves between Stretches have the region's ID in theirs, as `stretch:catalonia:12`, so that one region's can't be another's: every other ID in a track is a Network's already. The line measures (#160) are still worked out over every region built, so that their spot in the report is the whole map's.
- **A region whose build fails keeps its last files.** A Network with no copy of its timetables to build it from (#286), a trace more than 5% off its feed's shape (ADR-0004), a line order the solver can't find or a track file that wouldn't read back as the track built (ADR-0015) fails its region and no other. The region goes without new files, and the manifest names those its last build named, from the day before today on, so that the other regions are built and published as ever. It's logged, with its stack, and reported as a `region` spot, a problem spot, and its Networks' spots of the last report are carried over as they were, so that they don't show as gone from one report and new in the next. Where no region has any Trips today, or none builds, the build fails and publishes nothing, as it did.
- **The manifest names each region's days:** `regions: [{ id, days: [{ date, track, trips, from, to, noTrips? }], networks, extent? }], zoomedOut`, in the order of the regions' first Networks, which is the order the map lists the Networks in. A region's days are the day before the ones built, where its last build named it, and those built; one that failed keeps those its last build named from the day before today on, so it stays on the map for the days that build built, three at most, and goes from the manifest when none is left, so that a stale day never stands for today. Since #266 it names each region's Networks too, and where its Stations and track lie, west, south, east and north, outward to a thousandth of a degree, but for long distance's, and the file below zoom 7: every region's Networks, each Network's track as the map draws it below zoom 7 (#190), simplified by a tenth of a pixel at zoom 7 and to a ten-thousandth of a degree, and each region's Stations, by their IDs. A failed region's are those of the track file the manifest names for it, its last build's, read back from R2; where that can't be read, the build fails rather than lose the region's track below zoom 7.
- **The page loads the regions it needs, and joins them as one bundle,** as a build of all their Networks at once would have made it (`joinTracks()`): each region's Networks, Lines, shapes and strokes in turn, and each Station once, naming every Network whose Trains stop there. A region whose file fails to come is left out of its day, and fetched again with the next look. Since #266 it loads a region from zoom 7, where it draws Lines and Trains, once its extent meets the view grown by half its width and height each way; wherever the map is, the region of a `train=` link's Trip, by the Network its ID leads with, those that have a `station=` link's Station, by the file below zoom 7, and those within 1,500 m of the viewer that Nearby finds; and at every zoom, long distance's, and every region of a manifest from before #266, which names no extents. It never lets a region go, so a followed Train's stays loaded. Below zoom 7 it loads none for the view: the file below zoom 7 draws every region's Network track there and credits every region's Networks, and no Station dots are drawn there.

## Considered Options

- **One bundle for all of Spain,** as today. Rejected: long distance's track alone made the page crash, and one region's failure, as an OpenStreetMap trace gone wrong, stops every other region's publishing.
- **Regions worked out from the Stretches the Lines share.** Rejected at triage: long distance runs through every region, so it would join them all.
- **A region for each autonomous community.** Rejected: núcleos cross them, and a region is for loading together, not for administration.
- **One numbering of the Stretches across regions,** so that Catalonia's IDs are the whole bundle's. Rejected: each region's IDs would depend on the regions built before it, and on how many Stretches one that failed would have had.
- **Keeping the old manifest's shape too, for pages loaded before a deploy.** Rejected: the old page loads one file with every Network's Lines, which would need the whole bundle joined, written and published as well, from a failed region's last files too, and kept for good. The precedent is #28's: the daily build and the deploy run back to back, in one workflow.
- **Joining the regions' files in the build, for the page to load one.** Rejected: that's the one file.

## Consequences

- Lines of two regions that share track are drawn over each other, not side by side, and where they do, each draws as if alone: its Lines in the middle of the track, and its rails not marked as shared (#139). The build logs each such Stretch: a pair of regions, how many Stretches, how long, where, and which Lines. On 10 October 2026 there was one: Cercanías León's C1, which runs FEVE's line from León to Guardo, and Cercanías Bilbao's C4, which Renfe files from Bilbao to León along it, 118 km, with seventeen Stations in both regions' tracks, and one Station each on the map, naming both Networks. #368 left that train out of Bilbao's C4, which ends at La Calzada, so that the 15 regions share no Stretch, as their split rests on.
- A region's drawing is made from its own Networks alone, so a Line changing in one region moves none in another (as #277 asked of the fixed latitude), but it isn't always the drawing one graph of every Network made. On 10 October 2026, of the 10,471 strokes of the one bundle, 142 are not in a region's track as they were: 96 were those two Networks' sharing, which #368 ended, and 46 are strokes of another region whose graph the solver and the curves' ends settle another way once the others' Lines aren't in it: six Lines in a 425 m tunnel Stretch of Catalonia's zoom 7 graph are in another order, and 40 curves between Stretches elsewhere, in Madrid's mostly, are made from their other end, so that their points differ a little (since #448 it is the end whose strokes' numbers come first compared as numbers, so that a curve is a function of its own Lines and no longer follows how many strokes come before it, as the one graph's strings did). Every Line, Station, Trip, Closure, traced shape and Network track, and every centreline but those curves and the two regions' where they share, is the same.
- A dry run of the daily build on a Mac, with the feeds and rails cached, took 271 s before and 281 s after: reading the timetables, which 15 Networks repeat (#369), and `measures()` take most of it.
- The files a viewer loads for today come to 1,978 KB brotli against 1,897 KB: 1,453 KB of tracks in 15 files, the largest Catalonia's at 609 KB, where they were 1,376 KB in one, and 525 KB of Trips against 521 KB. The manifest, which the page reads every minute, is 8.7 KB (1.4 KB gzipped) against 0.6 KB.
- R2 gets 60 files for the three days, where it had 4, and the daily job's publishing takes about two minutes more, a `wrangler` call of 2 s each. Nothing deletes the files of days gone by, as before: a day's Trips are 0.5 MB brotli in all.
- The page, the recorder (`npm run record`) and the tests' fixtures read the regions through `daysOf()`, `joinTracks()` and `joinTrips()`.
- Since #266 the page asks for the files a view needs, not all 30: on a dry run of 11 October 2026 (the files of 10 October), at Barcelona at zoom 12, 3 files, 853 KB brotli, where it was 30, 1,516 KB: the file below zoom 7 (24 KB), Catalonia's track (440 KB) and its Trips (389 KB); at Madrid at zoom 12, 3 files, 191 KB; over Spain at zoom 6, the file below zoom 7 alone. The manifest, read every minute, grows from 8.7 KB to 9.9 KB, 1.15 to 1.49 KB brotli. Its change only adds to it, so a page from before #266 reads it as ever, and a page from after reads one from before by loading every region. The legend's count, the random follow, About's pills and the Closures lifted are those of the regions loaded, which grow as the map moves.
- The first build after this deploys finds yesterday's entry in the old manifest, which the map can't read, so it leaves it out: yesterday's Trains still running past midnight leave the map then, which a build in the afternoon doesn't touch. The old page can't read the new manifest, nor the new page the old one: until the deploy that follows the daily build, a page opened shows the basemap and no Lines. They run back to back, as they do. That first build has no files by region to keep for a region that fails, so one that does fails the build, as one Network's failure did before, and nothing publishes or deploys: the map would lose the region otherwise (`manifestOf()`). So does one whose last manifest couldn't be read.

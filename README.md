# Via Península

A live map of passenger trains moving on real track across Spain, starting with Catalonia: [viapeninsula.gariasf.com](https://viapeninsula.gariasf.com).

The domain language is in [CONTEXT.md](CONTEXT.md), the decisions in [docs/adr](docs/adr), and the v1 spec in [issue #1](https://github.com/gariasf/viapeninsula/issues/1).

## Working on it

You need Node 24 or later, the `unzip` command and osmium-tool (`brew install osmium-tool`). The daily build reads TMB's timetable with TMB's key: copy `.env.example` to `.env.local` and fill in `TMB_APP_ID` and `TMB_APP_KEY`, and NAP's `NAP_API_KEY` for Ouigo's timetable, which `npm run daily` loads from there.

```sh
npm install
npm run dev                  # the site at http://localhost:5173, reading data from viapeninsula-live.gariasf.com
npm test
npm run check                # typecheck
npm run daily -- --dry-run   # build today's bundle into out/ without publishing it, on today's feeds, kept in .cache/feeds/
npm run daily -- --dry-run --region catalonia   # build only that region's files (a change whose effects cross regions needs a full run)
npm run -s baseline          # print the out/ of main's dry run for its build tree and today, built once and shared by every worktree
npm run daily                # build it and publish it to R2
npm run deploy               # typecheck, build the site, and deploy it and the fetcher
npm run page -- '#map=12/41.3874/2.1686'   # shoot the map at 390×844 and 1280×800, light and dark
npm run perf -- S2 S5bcn     # the map's perf against milestone 1's budget
```

To check a change to the build, compare a dry run of your branch with main's on the same day's feeds: `rm -rf out`, a dry run, then `diff -r "$(npm run -s baseline)" out`, where after a `--region` run only that region's files in `days/` count (#730). The baseline is one dry run of `origin/main` for each tree of `src/build`, `bundle.ts`, `networks.ts` and `pieces.ts` and each Madrid day, kept in the main checkout's `.cache/baselines/` and shared by its worktrees, so a commit to main that touches none of them doesn't rebuild it; a run that finds another building it waits for that one. A dry run keeps the day's timetables in the main checkout's `.cache/feeds/`, which its worktrees share, and reads them from there till the next day, so every dry run of a day builds on the same feeds, which build the same files (#240). It reads OpenStreetMap's rails from the main checkout's `.cache/` too, kept a week, so that a branch's dry run shares with the baseline its day, its feeds and its rails, and differs from it only by the branch's code (#793). A timetable that one run couldn't download, and built from its last copy, which its log says, still sets that run apart. `--region <id>` builds one region, as `catalonia`, `cercanias-madrid` or `long-distance`, and writes only its files, byte for byte those a full run writes, but no manifest, file below zoom 7 or report; a change whose effects cross regions, as long distance's Lines share Stretches with Catalonia's, needs a full run.

Every browser check goes through `src/page/` (#729), on this Mac (an M4 Pro): Playwright's cached Chromium 1223 (`playwright-core` is pinned to 1.60.0, which pairs with it; never run `npx playwright install`, which prunes the cache other projects share), headless on the GPU through Metal, which it checks at launch and fails on in software. A batch waits for one of the Mac's three browser slots (`slots.ts`, in the repo's git dir, so every worktree shares them; a browser that didn't take one counts as taking one, the user's own Chrome apart) and is stopped at 10 minutes, with status 3; after 15 minutes' wait it exits with status 2, the check not run. Each page has a browser context of its own, as pages that share one crawl unless in front. The page is built from the tree (`.cache/page/dist-<the tree's folder name>`, as a worktree's linked `.cache` is the main checkout's) and served by Playwright's routes at the site's own address, so the live bucket's CORS lets it read the live files, with `window.map` set where the map is made, through the route, never in `main.ts`. `npm run page` takes `--out [dir]`, to serve a local bundle (`npm run daily -- --dry-run`'s `out/`) for the files it has, `--slow`, a link of 50 KB/s and 400 ms a request for every file but the site's own, which come at once, as from the cache, as #721's review used, `--wait <s>`, and `--at <capture>`, which replays a moment the fetcher captured, as a weekday's peak (#828): the capture's first snapshot (`history/<date>/<hour>.ndjson.gz` in the history bucket) is served for every poll and the page's clock set 5 s after it was made, with `--out` a mirror of that day's live files; and it exits 1 on a `pageerror`, its shots in `.cache/page/shots/`. A ticket's own script imports `launch()`, `openMap()` and `ready()` from `src/page/page.ts` and `withSlots()` from `slots.ts`. `npm run perf` runs each scenario named (`S2` a cold load, `S3` a zoom out and in, `S4` drags, `S5bcn` the map at rest, `S7` the next day's join, `S8` following a Train) 3 times, each round of runs a batch in all three slots, a cold context each, on the desktop (1440×900 at DPR 2) or with `--phone` (390×844 at DPR 3, the CPU slowed 4×), prints each check's median against `src/page/budget.json`, milestone 1's budget, and exits 1 on a breach; `--tree <dir>`, given twice, alternates a before's and an after's runs in one batch, `--out` and `--at` are `npm run page`'s, though S7's runs, which set their own clock, take no `--at`, `--pitch <deg>` tilts every scenario's view and keeps it through S3's jump and S8's follow (#213), and every run goes to `.cache/page/perf/runs.jsonl`.

The daily build reads the timetables of the Networks in `src/networks.ts`, Rodalies and the other 14 Cercanías núcleos, from Cercanías Madrid to Cercanías Zaragoza (all from Renfe's Cercanías feed, which it downloads once for them all), FGC, TRAM and the Metro (TMB's), and keeps their Trains: trams, metros, trains and funiculars, and no buses, but for those Renfe runs in a Line's Trains' place, which it makes Closures of (below). Where Renfe lists one Train as Trips that meet at a Station in the same minute, as Rodalies' R4 Trip of 33527 from Manresa to Rajadell and its RL4 Trip on to Lleida-Pirineus, or an RL4 Train's last call at Manresa and an R4 Trip of that one call, it makes them one Trip, named by the one with the most calls, RL4's, which keeps the IDs of the Trips it takes in, as Renfe's live data names the Train by each while it runs that part, and logs each join with its Train number and Station (#467). It gives each download 2 minutes, and tries one that fails once more, a minute later. A Network one of whose timetables still can't be downloaded or read, or gives it no Lines, is built from the copy of them that last built it, which the build keeps in `.cache/`, so the others build as ever; with no copy, its region fails (#286, #256). The bundle is built by region (ADR-0014): the Networks that name one region in `src/networks.ts`, as Catalonia's four do, or each Network alone, one region after another, each into a track file, the same for each day, and a Trips file for each day, of its own, named for the region, in `days/`. A track file stores its traced shapes as the pieces of track they share, and its slots as chains, which the map reads back as the shapes and slots the build made (ADR-0015); the build fails a region whose file wouldn't give them back. Beside it goes the region's decks file, named after it, `days/decks-<region>-<the track file's hash>.json`, which only a desktop loads: where each centreline its Lines are drawn along runs on a bridge, which a desktop draws as decks from zoom 14 (ADR-0016). A region whose build fails keeps the files of its last build in the manifest, from the day before today on, while the others publish, and is reported as a problem spot, whose `days` are how many days of those files the manifest still names for it, one fewer each build it fails, with its words for it: that it keeps them for that many more days, or has gone from the map once none is left, which the build comments on the Build report issue again, or has no files of a last build, as a region added by a config change whose first build fails has none (#452); the build that first makes a manifest by region, or can't read the last one, has none to keep, and fails whole instead. The manifest names each region's Networks and where it lies too, and the file below zoom 7, every region's Networks, with the short names their configs give some, Network tracks, simplified, and Stations, with their names, places and Lines, and Lines, which Search finds a Station by and names Networks by (#471), a failed region's from its last track file, so that the map loads a region's files only once it's in view from zoom 7, or a link or Nearby needs it, and draws every region's track below zoom 7 from that one file (#266). It logs where Lines of two regions share Stretches, which are drawn over each other, not side by side. It reads Renfe's long-distance timetable too, as AVE y Larga Distancia's Trains and Media Distancia y Avant's, which it draws (#262, #263): that timetable lists a Train as several Trips, one for each part of its run it sells, which it makes one Trip, from the one that runs the Train's whole way, from a Station none of its Trips calls at after another call to one none calls at before another, then the one with the most calls, then the one whose ID sorts first, whatever order the timetable lists them in (#402), dropping and logging any call of the others that lies outside the run they share, as where Renfe runs part of the way by road, and it leaves the Trains Rodalies or a núcleo lists too, by their Train number and a Station they share, to their timetable, and on a day theirs lists none of their Trips, those it lists on other days (#258), but for the calls their Trips don't make, by that number at that Station or by any number in the same minute, each run of two or more of which is a Trip of its own, as the Bilbao–León train's from Bilbao to Santibáñez de la Peña, León's C1 having its last 17 (#547). Where Renfe runs a Train by road though the timetable lists it as rail and no Alert informs its Lines, as Zaragoza–Teruel–Sagunto's, Almuradiel–Jaén's and Los Rosales–Cazalla-Constantina's, the Network's config names the Stations, with the notice, and the build leaves the Train out whole, logged and counted in the Network's Trips spot (#562, #263). As that timetable has no shapes, it traces each run of a Line's Trips, through the Stations they call at, on the rails of their gauge, and where a stretch has no path on it, on the others too, keeping to its own as far as it can, cut at Spain's border with the first call beyond it, as AVE Int's at Perpignan and Trencelta's at Valença do Minho, and logs each trace's length against the straight line through its Stations (ADR-0004, #259). AVE y Larga Distancia is a region of its own, long distance's, built last and loaded at every view, and Media Distancia y Avant one of its own too, built just before it and loaded from zoom 7 where the view reaches it (ADR-0014): its Trips are placed on their runs' traces, from each one's start to its end, and checked against their Line's top speed, as AVE's 300 km/h, its Stations are those they call at, and its track below zoom 7 is drawn over every other Network's (#262). It reports a hop traced more than twice its straight line and 10 km more, a trace that sets off from another of a Station's tracks than it came in on, with how far across it jumps, and the Trips of a run with a Station off the rails or a stretch with no path, which it leaves out rather than draw them straight across the country, Media Distancia y Avant's too since #263. Media Distancia y Avant's timetable failing, even with no copy, fails its region and no other, and the other regions' Trips then have no twins (#488). It traces each Line along OpenStreetMap's rails of its Network's own kind, a way with no gauge tag counting as every gauge's (ADR-0004, #479), and in a Network of two gauges, as Cercanías Asturias, Bilbao and Santander, of its own gauge alone, as the Network's config names it (ADR-0004, #366), and reports any stretch it can't trace. It filters the rails, and Spain's border, where it cuts the Lines (ADR-0010), out of Geofabrik's extracts of Spain, of the French regions along Catalonia's border and of Portugal with osmium (ADR-0009), keeps them in `.cache/` for a week, and fails if a traced shape's length strays more than 5% from the feed's (100 m on shapes under 2 km, such as funiculars). It then places each of the day's Trips on its track. One calling at a Station off its track, or that would have to run faster than its Network's top speed along it, doesn't fit its feed's shape, and is traced through its own Stations instead, once for all the Trips that call at the same, along the rails its Line's shapes were traced on and the track they took where they share it, and placed on that trace, which its Line has too, where its times fit it, as Cercanías Madrid's C2 Trips by Fuente de la Mora, which Renfe's shape runs by Atocha, and Cercanías Santander's and Valencia's to the Stations beyond their shapes (#280). A Trip that doesn't fit its trace either, or whose Stations have no path along the rails, is reported and left out, as the long-distance timetable's are. The Stations a feed's shape leaves out, as they lie off it on a branch, are logged for each shape, and reported only where a Station of the run is one that no Trip of its Line placed on a trace of its own calls at on the days built, as Santander C3's Puente Agüero, Villaverde de Pontones and Hoz de Anero no longer are, a Trip's trace calling at them (#601). Where Renfe's timetable puts a Station off the track its Trains stop on, as it puts Asturias' El Entrego at a FEVE station 0.4 km from Adif's, the Network's config says where the Station is, with its source in OpenStreetMap, and the build lists each one it applies (#367). Where a timetable shortens a Station's name, as TRAM's feeds write Ciutadella | Vila Olímpica as `Ciutadella|V.O.`, the Network's config spells it as its operator's own site does, with that page as the source, and the build lists each one it applies too (#571); it's the headsign of any Trip that ends there too, as TRAM's timetables have none. Where Renfe files under a núcleo's Line a train that runs on into another Network, as FEVE's Bilbao–León train under Cercanías Bilbao's C4, the Network's config names a Station beyond it, and the build leaves out each Trip that calls there, with the Stations and track only it has, and names them in the Network's Trips spot of the report, with how many (#368). Renfe lists the buses it runs in a Line's Trains' place as Trips of bus routes named as the Line's, though it runs most of them beside the Line's Trains: each day's bundle carries the Closures they make only where none of the Line's Trains runs that day. The build cuts each bus's run on its Line's track at the Stations the Line's Trains call at that day, and closes each part between them that none of those Trains calls at both ends of, from the first bus over that part to the last (ADR-0012), as R13's Les Borges Blanques – La Plana-Picamoixons on 7 Oct, where its buses ran on to Lleida beside its Trains. It reports where they run where their Line has no track, as R3's buses from Fabra i Puig to La Garriga, where no R3 Train runs (#340), and a TRAM Trip whose stop numbers (`stop_sequence`) don't run 1…n, as TRAM's trip updates name a stop by its number in its Trip, and the Trip's call at that number less one is its Station only where the numbers run so (#406). It reports too each route name in Renfe's long-distance timetable that neither of its Networks takes, compared as written, as a route under a name that's new, or written otherwise than before, has its Trips in neither (#401). What it reports, the line measures (#160), each Network's Trips on each day of the week, and its Closures today, it also writes to `out/report.json`: each spot once however many of a Line's shapes or days name it, keyed as `keyOf()` in `src/build/report.ts` has it (section 3 of `docs/research/build-report.md` is the design of #219's eight kinds), so that the next build names it the same, and never by a Trip's ID or a date. It publishes `report.json` after the manifest, and the next build diffs its own against it: the spots new since, then those gone, then those whose numbers moved (a length by more than a point, a Network's Trips today only where they're more than a quarter fewer than the last report's for the same day of the week, though it keeps them all, as a holiday runs a Sunday's timetable, and a Trip count or a measure by any), each with links to the map at the spot, which rings it until the next tap (but not a run of Stations left out on a branch, whose view is fitted to show it, #388), and to OpenStreetMap, to see it, edit it and open the ways its Stations are on. It prints the diff, or one line where nothing changed, and in Actions writes it to the run's job summary. Where a problem spot is new (a run of legs that keeps the feed's shape, a turn-back, a branch, a hop traced more than twice its straight line and 10 km more, a trace that jumps across a Station's tracks, Trips left out, a TRAM Trip whose stop numbers don't run 1…n, a route name no Network takes, a Network with no Trips on a day, one built from its copy, or a region whose build failed, but never a length, a node, a curve that wiggles, a hairpin or a turn-back's curve, the measures, a Network's Trips or Closures, or buses where their Line has no track), it also comments on the standing [Build report](https://github.com/gariasf/viapeninsula/issues/290) issue once it has published, with the new spots, their links and the run's link. [docs/review-a-build-report.md](docs/review-a-build-report.md) says what to do with a new spot, and how `npm run snippet` cuts one into a test's fixture.

The fetcher is a Durable Object in a Worker of its own, with no routes, and is made in Western Europe, near its live feeds, by a location hint (ADR-0003). It reads its live feeds from `LIVE_SOURCES` in `src/networks.ts`, each with the adapter for its format in `src/fetcher/step.ts`. A feed can serve several Networks, as Renfe's Cercanías files have every núcleo's Trains: each Train goes to the Network its feed's config names for how its ID starts, and the feed's freshness is each of those Networks'. About every 20 s it fetches Renfe's Cercanías live data and TRAM's, every other time Renfe's long-distance live data, whose files update every 14–30 s, and the Metro's, which TMB asks for no more than every 30 s, and every 2 minutes FGC's and Euskotren's trip updates, of which it keeps the Trips running, and writes `snapshot.json` to R2 with a 15 s cache lifetime. It keeps each run's snapshot too, for the Delay history: the first run after each 5 minutes puts those 5 minutes' snapshots as one gzipped file, a line each, `history/<UTC day>/<hhmm>.ndjson.gz`, in a bucket of its own with no public domain, `viapeninsula-history`, whose lifecycle rule deletes each 7 days later (ADR-0003, #806). It reads Renfe's alerts too, on every run, with a conditional request that Renfe answers with 304 while its file is unchanged, and TRAM's every 5 minutes, with the access token it keeps for TRAM's live data. It writes those on the Lines of the map's Networks, and Renfe's on any Station, to `alerts.json` beside the snapshot, with when it last read each feed and when its file last changed (Renfe's Last-Modified, or the file's header timestamp where it has none), and a minute's cache lifetime: whenever a feed's Alerts change or a try at it starts or stops failing, and at least every 5 minutes, which is what gives each its time of reading and of its file's last change (ADR-0012, #390). FGC's API allows 5,000 requests a day to each IP, and a refresh takes 2: while fewer than 1,000 are left the fetcher slows FGC to every 5 minutes, and once none are, it waits for 00:00 UTC. TRAM's API wants an access token, which the fetcher asks for with TRAM's credentials and keeps for the hour it lasts. TMB's predictions name each metro train by its Block rather than its Trip and say only when it's expected at its next Stations, so the map runs each as the Trip on its Line headed its way whose timetable has it at its next Station closest to then, and keeps it on that Trip while the Trip still calls at the Station it comes to next. The site fetches the snapshot about every 20 s while its tab is visible, and `alerts.json` about once a minute, for the Alerts a followed Train's card and a Station's board show (#342), and a tap on a Line's stroke or on a Closure, each under a note of when its feed's file last changed where that's over a day before the map's time, as Renfe's stood unchanged from 7 Oct, 9:32, for days, which its 304s can't say (#390), and for the Closures it draws on their Lines: those an Alert's words name, read with what they say of each stretch, but not an Alert about some of a Line's Trains, as one named by where it leaves ("Tren con salida…") or by where they come from ("para los trenes con origen…"), the two wordings 9 Oct's file has (#396), and the timetable's, between their two Stations, where the Line's track runs by both (#341). A TRAM Alert's Closure is drawn only at the moments its timetable has some Trip of any of the Alert's Lines running within half an hour either side and none of them calling at both its Stations, as TRAM's Alerts show days before their works (#397). Within a closed one, a Train isn't drawn, and boards show it not stopping at the Stations between its two, unless it's Live within it, as live data wins (#345). A followed Train that runs into one stays in its card, as a Trip still to come that doesn't run between the Closure's Stations, with its Line's Alerts, and its strip marks those Stations as not stopped at, until it's drawn again at the far side or its Trip ends (#420). Once a report has a Live Train of its Line within one an Alert makes, pinned to a Station between its two or more than 200 m within them along its track, it hides none of that Line's Trains until the Alert changes, its period, effect or words, though it's still drawn, as Renfe's Alerts have no end: on 10 Oct its 7 Oct ones for R1 and R3 were still listed while both ran. The page remembers what it has lifted while it's open (#345). An `http://` or `https://` address in an Alert's words is a link wherever the cards and a tap show them, written as the operator gave it and opening in a new tab, with a `.`, `,`, `;`, `:` or `)` that ends it left outside, and the words are otherwise as they were but for the word after the address that says it opens a tab, which only a screen reader reads (#391, #585). A fetch that fails, comes back empty, or finds data that says it hasn't been updated since the last try leaves that feed's last good reports in the snapshot, and the feed's freshness there says what went wrong. Renfe's long-distance files name any part of a Train's run, so the snapshot names each of their Trains by its Train number, with its GPS, and the map finds its Trip by that number in any Network, on the day nearest in time, but for a Train its Network's own feed reports too, which goes by that feed: so R15's 17050, which only those files report, is Live too (#261). A Train in them is Cancelled only where every trip update for its number says so and Renfe gives it no position, and only once its Trip is due to leave its first Station, as such an update can't say which run (#429). Where Renfe's trip updates say a Train won't stop at some of its Trip's Stations, as where Renfe cuts it short or starts it late, the snapshot carries them, kept for 3 hours after Renfe last lists the Trip, and the map runs the Train only as far as the Stations it stops at, and boards show it not stopping at the rest (#346). Where a feed that covers several Networks works but has none of one Network's Trains, as Renfe's Cercanías files drop Madrid's now and then, that Network's last reports stay for two tries more, but not those of Renfe's long-distance files, which name a Train by its number alone, not by a Trip of its Network, and each try that finds it missing, up to the one that drops them, goes in the fetcher's logs, which Workers Logs keeps for 7 days. On the map, a Train that live data stops reporting stays Live through two of its feed's updates and turns Scheduled at the third, keeping its last Delay for 30 minutes, as a metro Train does at once when its Block goes on to run another Trip. A banner names each Network whose feed has missed three, or works but has had none of its Trains in it for three (five, where its feed covers other Networks too, but three for Renfe's long-distance files' two, whose last reports aren't kept) while its timetable has at least 5 of them on the map, but only while one of its Trains is in view, or the map follows one (ADR-0010). Its Worker's cron trigger starts it every minute, unless it's running already. To run it locally, writing to a local copy of the bucket, with TRAM's credentials and TMB's key in `src/fetcher/.dev.vars`, which git ignores:

```sh
npx wrangler dev -c src/fetcher/wrangler.jsonc --test-scheduled
curl 'http://localhost:8787/__scheduled'   # start it
npx wrangler r2 object get viapeninsula-live/snapshot.json --local -c src/fetcher/wrangler.jsonc --pipe
npx wrangler r2 object get viapeninsula-live/alerts.json --local -c src/fetcher/wrangler.jsonc --pipe
npx wrangler r2 object get viapeninsula-history/history/2026-10-16/1010.ndjson.gz --local -c src/fetcher/wrangler.jsonc --pipe | gunzip   # a 5-minute slot's snapshots, in UTC, once it has ended
```

The site speaks Catalan, Spanish, Basque, Galician and English. Every string it shows is in `src/web/i18n.ts`, in all five, except names: Stations and Lines are shown as the operators publish them, but for the word before a Station's name in Catalan and Galician, which runs into its article or, in Catalan, elides before its vowel, as those languages write it (`al Prat`, `d'Arenys de Mar`, `pels Monjos`, `da Coruña`, `ao Porriño`, #606), and a Catalan name's La, Les or L' that goes in lower case after it (`a la Garriga`, `per l'Hospitalet`), and the credits name their sources as those sources do. The Basque and Galician are machine-translated, and About says so in each, linking GitHub for corrections, until a speaker has checked them (#327). Dates, times and numbers are written as the browser's `Intl` writes them in the viewer's language, or in Spanish where it has no data for that language, as Chrome has none for Basque or Galician. The basemap names countries, regions, seas, rivers and airports in the viewer's language, or in Spanish for Galician, which its tiles have no names in, and everything else, from towns to streets, as its signs do. A link that opens in a new tab, as About's, the credits' and an Alert's words' do, has `noopener noreferrer` and says so after its text in a word only a screen reader reads, in the viewer's language, which `opensInNewTab()` in `src/web/newTab.ts` gives all of them (#585).

## Cloudflare setup

Done once. The R2 bucket that serves the data, its custom domain and its CORS policy:

```sh
npx wrangler r2 bucket create viapeninsula-live
npx wrangler r2 bucket domain add viapeninsula-live --domain viapeninsula-live.gariasf.com --zone-id f6becb73149a3725d72afa19c9478eb5
npm run cors
```

The history's bucket, with no domain, and its lifecycle rules, which delete what's under `history/` 7 days after it's put (#806), and the compacted days under `compacted/` after 400 (#807):

```sh
npx wrangler r2 bucket create viapeninsula-history --location weur --update-config=false
npx wrangler r2 bucket lifecycle add viapeninsula-history expire-history history/ --expire-days 7 --force
npx wrangler r2 bucket lifecycle add viapeninsula-history expire-compacted compacted/ --expire-days 400 --force
```

A Cache Rule in the dashboard caches viapeninsula-live.gariasf.com at the edge for as long as each file's `Cache-Control` says, ignoring query strings.

TRAM's credentials and TMB's key, as the fetcher's secrets, fed from `.env.local` without being printed:

```sh
for name in TRAM_CLIENT_ID TRAM_CLIENT_SECRET TMB_APP_ID TMB_APP_KEY; do
  node --env-file=.env.local -e "process.stdout.write(process.env.$name)" | npx wrangler secret put $name -c src/fetcher/wrangler.jsonc
done
```

## The daily build in Actions

`.github/workflows/daily.yml` runs `npm run daily` in GitHub Actions and publishes to R2. The fetcher's Worker starts it at 00:30 UTC through GitHub's workflow dispatch, GitHub's own schedule starts it at 03:30 UTC in case that one doesn't come, and the Run workflow button in the Actions tab starts it whenever it's wanted. Running it again for the same days publishes the same files, so the second run each day is harmless. Its secrets, fed from `.env.local` without being printed: TMB's key, NAP's and the R2 token as Actions secrets, the R2 token under the name Wrangler reads there, and the dispatch token as the fetcher's secret:

```sh
for name in TMB_APP_ID TMB_APP_KEY NAP_API_KEY; do
  node --env-file=.env.local -e "process.stdout.write(process.env.$name)" | gh secret set $name
done
node --env-file=.env.local -e "process.stdout.write(process.env.R2_API_TOKEN)" | gh secret set CLOUDFLARE_API_TOKEN
node --env-file=.env.local -e "process.stdout.write(process.env.GITHUB_DISPATCH_TOKEN)" | npx wrangler secret put GITHUB_DISPATCH_TOKEN -c src/fetcher/wrangler.jsonc
```

`.github/workflows/punctuality.yml` runs after each daily build: `npm run punctuality` replays the service day before through the engine, from the fetcher's history, and writes the day's record to the history's bucket, a file for each Network, `<day>/<network>.json`, with the day's history compacted under `compacted/` (#807), and each day's bundle files the manifest names, `<day>/files.json`, which a later replay joins the day before by. It reads and writes the bucket with the same R2 token. `npm run punctuality -- --day 2026-10-17 --dry-run` writes the files to `out/punctuality/` by your wrangler login, and puts none.
